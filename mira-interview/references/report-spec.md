# 单次面试诊断文档规范

报告使用 Markdown，标题包含能够可靠确认的公司、岗位和日期。开头列出本次归档的简历、录音、JD 和完整逐字稿路径。

## 1. 面试基本信息

以表格列出公司、岗位、轮次、日期、时长和面试形式。已有信息明确写出；只有高置信度推断才可填写，其他情况统一填 `-`。不要在表格中展示低置信度猜测，也不需要逐字段附加证据和置信度。

## 2. 全过程逐段点评

严格按实际发生顺序编号。每一段包含：

- 环节及时间范围
- 面试官提问原文
- 候选人回答原文
- 考察点
- 点评与 1–5 分评分，必要时拆分内容、结构、证据、表达
- 具体修改意见
- 推荐答法

提问和回答必须完整呈现逐字稿中的对应内容。按上下文识别面试官提问与候选人回答，并分别聚合被时间片拆开的同一角色连续发言；原始单个时间片混合双方时，按语义拆分后分别归入提问或回答。长回答、连续追问和案例讨论同样不得摘录、概括或截断；完整性优先于报告篇幅。口头犹豫、重复、断裂或模糊不清的局部可用 `...` 整理，但不得用省略号代替可辨认的实质内容。推荐答法只能使用材料中已存在的事实，未知信息以 `[需补充]` 标记。

## 3. 面试官视角评价

先给“倾向通过 / 待定 / 倾向不通过”的结论、置信度和依据，再给分维度评分、亮点与不足。

存在可核验的企业官方招聘能力模型时，使用其原始维度并注明官方来源。否则必须根据本次具体岗位、目标职级、JD 和面试轮次建立岗位专属通用标准；不得直接套用一套适用于所有岗位的固定维度。每个维度包含分数、面试证据、风险或信息缺口，并区分“本场未展现”和“候选人不具备”。

## 4. 总体结论与改进计划

总结最影响结果的 3–5 个判断，并按优先级给出：

- 下一场面试前立即修改的答法
- 需要补充或量化的经历证据
- 需要专项训练的能力或表达模式
- 可执行练习及验收标准

结尾列出信息缺失、转录疑点和无法验证的判断限制。

## 5. References

`References` 必须是诊断报告的最后一节。生成报告期间通过互联网、企业官网、招聘网站、公开文章、研究资料或其他公开渠道检索到并实际使用的任何信息，都必须引用，包括企业人才评价模型、岗位能力标准、公司业务信息和招聘要求。

- 在正文中相关事实、标准或判断依据之后就近标注引用，不得只在末尾堆放来源而不建立对应关系。
- 优先引用企业官网、官方招聘页面、政府或研究机构等第一方来源；使用非官方来源时明确其来源性质。
- 每条 Reference 至少包含来源标题、发布机构或作者、发布日期（可获得时）、访问日期和可点击 URL。
- 不将简历、JD、录音或逐字稿等本次输入材料列入公开信息 References；这些材料在报告开头的输入清单中记录。
- 如果生成报告时没有使用任何公开信息，仍保留本节并写“无”。
