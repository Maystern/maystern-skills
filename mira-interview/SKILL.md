# Mira Interview

基于某一场面试对应的简历版本、面试录音和岗位 JD，生成有证据、可执行的单次面试诊断。三项材料均为必需输入；缺少任一项时，明确指出缺失项，不使用其他版本或猜测内容替代。

## 路由

- 先检查项目根目录下的 `.mira-interview/config.env`。配置存在且有效时直接使用，不重复初始化。
- 配置不存在或无效时，读取并执行 [初始化配置](references/setup.md)。
- 需要转录时读取 [音频转录说明](references/transcription.md)。
- 生成报告时读取 [诊断文档规范](references/report-spec.md)。

## 项目文件约束

以 Codex 当前工作目录为 `PROJECT_ROOT`。除用户明确指定其他位置外，所有新建或下载的文件均位于该目录内：

```text
PROJECT_ROOT/interview-artifacts/
├── models/
└── <case-name>/                    # 公司名-日期-轮次，例如 acme-20260911-r1
    ├── inputs/                     # 简历、JD、原始录音的归档副本
    ├── transcription/
    │   └── <model-name>/           # 该模型生成的 WAV、JSON、TXT、SRT、完整 Markdown 逐字稿
    └── reports/
        └── interview-diagnosis.md
```

- `<case-name>` 使用“公司名 + 日期 + 轮次”，例如 `acme-20260911-r1`。在保留语义和可识别性的前提下尽可能精简：日期使用 `YYYYMMDD`，轮次优先使用 `r1`、`r2`、`hr`、`final` 等短写；不包含岗位、随机 ID 或无意义序号。无法从材料中确认公司、日期或轮次时，向用户询问。
- 在分析和转录前，必须先创建 case，并将本次使用的简历、JD、原始录音分别复制到 `inputs/`。归档保留原扩展名，不修改源文件。
- 不覆盖源文件或已有产物。发生重名时，使用明确的版本后缀。
- 每次转录写入 `transcription/<model-name>/`，其中 `<model-name>` 取自当前配置的 `WHISPER_MODEL_NAME`。切换模型配置时创建新的模型目录，保留其他模型生成的全部转录产物；同一模型目录已有产物时仍拒绝覆盖。
- 新下载的模型放入 `interview-artifacts/models/`。已有模型在该目录创建软链接。配置文件始终引用项目内路径。

## 工作流

1. 定位与本场面试严格对应的简历、JD 和录音。
2. 从可靠材料确认公司、日期和轮次，以精简的“公司名-日期-轮次”创建 case 目录，并在任何处理前归档三项原始输入到 `inputs/`。岗位仅用于报告，不用于 case 命名。
3. 检查 `.mira-interview/config.env`。仅在配置缺失或无效时执行初始化。
4. 没有可靠逐字稿时按 [音频转录说明](references/transcription.md) 转录。转录时明确提供“仅有一位面试官和一位候选人的面试对话”这一场景，并强制生成完整 Markdown 逐字稿。根据提问、回答、追问和语气等上下文推断发言角色，分别聚合面试官和候选人的连续发言；同一原始时间片混合双方发言时也要按语义拆分。
5. 按真实顺序覆盖完整面试，包括开场、自我介绍、所有提问与追问、候选人反问和收尾。
6. 如需企业招聘能力模型，仅采用能够核验的企业官方公开材料；未找到时，建立与该具体岗位、职级和面试轮次相匹配的评价标准。
7. 按 [诊断文档规范](references/report-spec.md) 生成报告。事实、合理推断和未知信息必须区分；检索并使用的所有公开信息均须在正文就近引用，并汇总到报告最后的 `References`。
8. 检查三项输入已归档、完整逐字稿已生成、全过程无遗漏、外部信息引用完整、打分尺度一致、推荐答法未虚构经历、全部产物位于项目目录。

## 评价原则

- 不凭空推断面试官心理、录用结果或淘汰原因。
- 面试官视角结论必须包含置信度及依据。没有真实结果时，使用“倾向通过 / 待定 / 倾向不通过”。
- 默认使用 5 分制：1=明显不满足，3=基本满足但有缺口，5=证据充分且明显超出预期。资料不足时标“无法评分”。
- 推荐答法只能重组和强化材料中的真实经历；缺少信息时使用 `[需补充：…]`，不得编造项目、职责、数字或技术细节。
- 原文保留转录时间戳。犹豫、听不清或模糊断裂处用 `...` 表示；对已有具体文字但疑似识别错误的内容标记 `[疑似转录：…]`。
- 根据对话功能和上下文将发言映射为“面试官/候选人”，并将同一角色连续、完整的语义单元聚合。无法判断的局部不强行归属，标记为“角色未确定”。
- 口头犹豫、重复、断裂或听不清的局部可整理为 `...`，但不得删除或改写能够辨认的实质内容。
- 建议具体到内容、结构、证据或表达动作，并按影响和紧迫性排序。

## 完成标准

1. 生成完整逐字稿：`interview-artifacts/<case-name>/transcription/<model-name>/interview-transcript.md`。
2. 生成面试诊断报告：`interview-artifacts/<case-name>/reports/interview-diagnosis.md`。
3. 在回复中返回上述两个文件的项目内可点击链接。
